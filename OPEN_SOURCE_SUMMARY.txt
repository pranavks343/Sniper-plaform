   • CircuitBreaker — halt trading on loss/drawdown

   • PPOExecutionAgent — RL-based order execution

   Strategy Engine:
   • MetaLabeler — ML-based trade labeling (XGBoost)
   • PositionSizer — Kelly Criterion, volatility-adjusted sizing

   Brokers:

   • DhanBroker — Full DhanHQ adapter

   • MarketSimulator — GBM synthetic data generation
   • TradingLoop — Main orchestration loop
   • StrategyLifecycle — State machine lifecycle

   Utilities:
   • structured logging
   • environment config management

💡 USAGE EXAMPLES

Install:
   pip install sniper-framework

Use in your code:
   from sniper import CircuitBreaker, GreeksCalculator
   
   breaker = CircuitBreaker(max_daily_loss_pct=0.02)
   calc = GreeksCalculator()

Use with FastAPI:
   from fastapi import FastAPI
   from sniper import EventBus
   
   app = FastAPI()
   bus = EventBus()
   
   @app.post("/orders")
   async def place_order(order: Order):
       await bus.publish("ORDER_PLACED", order)

Use with Celery:
   from sniper import BacktestEngine
   from celery import Celery
   
   celery = Celery()
   
   @celery.task
   async def run_backtest(strategy_id):
       engine = BacktestEngine()
       results = await engine.run(...)

✅ BENEFITS OF SEPARATION

For Users:
   ✓ Can use sniper-framework independently
   ✓ Don't need sniper-platform UI
   ✓ Integrate with their own systems
   ✓ Available via pip (simple installation)

For Contributors:
   ✓ Can contribute to framework or platform independently
   ✓ Clear scope (library vs application)
   ✓ Easier to manage versions
   ✓ Community can fork and extend

For Organization:
   ✓ Cleaner separation of concerns
   ✓ Framework can be open-sourced independently
   ✓ Platform can use framework as dependency
   ✓ Both can evolve separately
